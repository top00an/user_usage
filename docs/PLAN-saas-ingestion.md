# 기획 — 멀티테넌트 SaaS 수집(인제스트) 아키텍처

> 상태: 초안(2026-08-09), **일부 개정(2026-08-10)**. 결정된 방향 — **멀티테넌트 클라우드 SaaS ·
> 퍼스트파티 수집기 단일 경로 · 클라이언트는 Claude Code 훅 + 백그라운드 에이전트 병행.**
> 이 문서는 그 방향의 설계·단계·리스크를 적는다.
>
> ⚠ **OTLP 경로는 제거됨(2026-08-10).** 사유: 공식 Claude Code OTel 규약(`claude_code.*`)과
> 비호환인 자체 규약(`claude.*`)이라 "표준처럼 보이지만 표준이 아닌" 반쪽 자산이 됐다. 제품에서
> 제외하고 **퍼스트파티 수집기 단일 경로 + 멀티플랫폼(Codex·Gemini) 확장**으로 전환한다.
> 아래 OTLP 관련 서술(§3.1·§4·§7 Phase 2·§8)은 **이력으로만 남긴다 — 현행 설계가 아니다.**
> 삭제된 것: `POST /v1/logs` 수신구, `GET /api/usage/export/otlp`, `go/internal/otlp` 패키지,
> `docs/SPEC-otlp-claude.md`.

## 1. 목표

여러 조직(org)이 가입해 **자기 팀의 Claude Code 사용량·비용**을 보는 SaaS. 각 개발자 머신에서
집계가 올라오고, 조직 경계로 완전히 격리된다. 표준 관측 파이프라인(OTel)을 쓰는 고객과, 아무것도
없는 고객 둘 다 5분 안에 온보딩된다.

## 2. 이미 가진 것 (재사용 자산)

| 자산 | 위치 | SaaS 에서의 역할 |
|---|---|---|
| 인테이크 엔드포인트 | `POST /api/usage` (`go/internal/httpapi/usage.go`) | 퍼스트파티 수집 경로의 뿌리 |
| 테넌트 격리 | `tenant` + RLS(`app.tenant_id`, `db/rlsguard.go`) | **멀티테넌시의 핵심** — org=tenant 로 그대로 승격 |
| 집계 스키마·멱등 | `intake`·`store`(session UPSERT) | 재전송 안전·증분의 기반 |
| 데이터 정책 필터 | `intake.safeKeyword`, `collector/internal/policy` | 시크릿·PII 서버/클라 이중 방어 |
| 수집기 | `collector/` (jsonl→POST, 멱등·증분) | 백그라운드 에이전트 경로 |
| 비용·통계 | `cost`·`stats` | 조직별 대시보드 그대로 |

**핵심: 백엔드의 80%는 이미 멀티테넌트다.** RLS·테넌트 주입이 서 있고, 인테이크가 멱등이다.
SaaS 화의 실제 작업은 **① 인증/온보딩 ② 인제스트 표면(퍼스트파티 단일) ③ 클라이언트(훅) ④ 운영**이다.

## 3. 타깃 아키텍처

```
[개발자 머신]                         [클라우드 SaaS]
 Claude Code                          ┌─────────────────────────────────────┐
   │ SessionEnd 훅 ──(집계 푸시)──────▶│  Ingest Gateway                      │
   │                                   │   └─ /api/usage      (퍼스트파티)     │
 백그라운드 에이전트 ─(백필·누락보정)─▶│        │  정규화 → intake            │
   (~/.claude jsonl)                   │        │                             │
                                       │   인증: org 인제스트 키 → tenant     │
                                       │        │                             │
                                       │   store(RLS app.tenant_id) → pg      │
                                       │   dashboard(web) ── org 로그인 ──────│
                                       └─────────────────────────────────────┘
```

### 3.1 인제스트 표면 (단일 경로, 한 정규화)
- **퍼스트파티** `POST /api/usage` — 우리 집계 shape 그대로. 훅·에이전트가 쓰는 **유일한** 경로.
- 같은 정책 필터·같은 멱등·같은 RLS 를 통과한다. 표면 하나, 코어 하나.
- ~~**OTLP 호환** `POST /v1/logs` — 표준 OTel Collector/SDK 수신구~~ →
  **제거됨(2026-08-10).** 사유: 공식 Claude Code OTel(`claude_code.*`)과 비호환인 자체 규약이라
  제품에서 제외. 확장 방향은 OTLP 가 아니라 **멀티플랫폼(Codex·Gemini) 수집기**다.

### 3.2 클라이언트 (수집 소스, 병행)
- **Claude Code 훅(1차)**: `SessionEnd`(또는 Stop) 훅이 방금 끝난 세션의 집계를 계산해 즉시 푸시.
  실시간·설치 간편(설정 스니펫 한 줄). 대부분의 데이터가 이 경로로 온다.
- **백그라운드 에이전트(보정)**: 현 `collector/`. 훅이 못 잡은 것(훅 미설치 기간·과거 세션·훅 실패)을
  `~/.claude/projects/**/*.jsonl` 에서 백필. 증분 체크포인트로 중복 없음(서버 멱등이 2차 방어).
- 둘은 **같은 페이로드·같은 인제스트 키**를 쓴다. 훅=신선도, 에이전트=완전성.

### 3.3 인증 / 온보딩 (멀티테넌시)
- org 가입 → **인제스트 키**(prefix 로 org/tenant 식별, 예: `uu_ing_<org>_<rand>`) 발급.
- 키 → tenant 매핑을 게이트에서 조회해 `app.tenant_id` 주입 → 기존 RLS 가 격리를 강제.
- 대시보드 열람은 별도 **org 사용자 로그인**(SSO/이메일). 보고(intake) 키와 열람 토큰 분리 —
  이미 코드베이스가 "보고/열람 토큰 분리" 원칙을 가짐(git 이력 참조).
- 설치 UX: 온보딩 화면이 **훅 스니펫 + 에이전트 원라이너**를 org 키가 박힌 채로 복붙 제공.

## 4. ~~OTLP ↔ Claude 사용량 매핑~~ — 제거됨(2026-08-10, 이력)

> 이 절의 설계는 **더 이상 유효하지 않다.** 사유: 여기서 정의한 `claude.*` 확장은 공식 Claude Code
> OTel 규약(`claude_code.*`)과 비호환이라, 표준 파이프라인 호환이라는 원래 목적을 달성하지 못한다.
> 남은 것은 "표준처럼 보이지만 표준이 아닌" 자체 규약뿐이라 제품에서 제외했다.
> 왜 그런 시도를 했는지 알 수 있도록 아래 매핑안만 기록으로 남긴다.

- 표준: `gen_ai.usage.input_tokens`·`output_tokens` → input/output. `gen_ai.request.model` → 모델.
- **Claude 특수(표준에 없음)**: cacheRead·cacheCreate·`cc1h`(ephemeral_1h)·7축(tool·bash·slash·skill·
  agent·mcp·keyword) → `claude.*` 네임스페이스로 확장하려 했다 — **이 확장이 비호환의 원인이다.**
- 전송 단위: 세션=로그 레코드, 토큰=메트릭. 역방향 export(`GET /api/usage/export/otlp`)도 함께 제거했다.

## 5. 보안·컴플라이언스 (멀티테넌트 필수)
- 테넌트 격리 회귀 테스트(크로스테넌트 0)를 CI 게이트로 — 이미 pg 크로스테넌트 테스트 존재.
- 인제스트 키: org 스코프·회전·폐기. rate-limit·per-tenant 쿼터.
- 데이터 정책 유지: 집계만, 프롬프트/경로/인자 미수집, keyword 90일 보존·서버 재필터.
- 격리 감사 로그, 보존/삭제 정책(고객 이탈 시 데이터 파기), 리전/데이터 거주 옵션(엔터프라이즈).

## 6. 과금 훅
사용량 기반 제품이라 과금이 자연스럽다 — 좌석 수 또는 관측된 세션/토큰량. 인제스트 키·tenant 단위로
카운트가 이미 잡히므로 미터링을 그 위에 얹는다(Phase 3).

## 7. 단계별 로드맵

| Phase | 목표 | 핵심 작업 |
|---|---|---|
| **1 — 멀티테넌트 퍼스트파티** | org 키로 여러 조직이 훅/에이전트로 수집, 격리된 대시보드 | 인제스트 키↔tenant 매핑·발급, org 로그인, SessionEnd 훅 배포물, rate-limit, 격리 CI 게이트 |
| **2 — ~~OTLP 호환~~ → 멀티플랫폼 수집** | ~~표준 OTel 로도 수집~~ → Codex·Gemini 등 타 플랫폼 사용량도 같은 퍼스트파티 경로로 수집 | **OTLP 안(`/v1/logs`·`claude.*` 속성·export)은 2026-08-10 제거** — 공식 `claude_code.*` 와 비호환. 대체: 수집기의 플랫폼별 파서 확장 |
| **3 — Self-serve + 과금** | 가입·키발급·설치·결제 자동화 | 온보딩 UX, 미터링/청구, 쿼터·플랜, 엔터프라이즈(SSO·데이터 거주) |

## 8. 리스크 / 오픈 이슈
- **훅 계약 안정성**: Claude Code 훅 이벤트/페이로드 스키마 의존 — 버전 변화 대비 에이전트 백필이 안전망.
- ~~**OTLP 매핑의 표현력**~~ — **이 리스크가 현실화되어 OTLP 를 제거했다(2026-08-10).** 캐시·cc1h·7축을
  표준 속성으로 못 담아 `claude.*` 확장이 필요했고, 그 확장이 공식 `claude_code.*` 와 어긋나
  "표준 호환"이라는 목적 자체가 성립하지 않았다. 결론: 퍼스트파티 경로가 1급이 아니라 **유일**하다.
- **멀티테넌트 전환의 실측**: pg RLS 는 검증됐으나 "키→tenant 게이트 + rate-limit" 는 신규 코드 → 격리
  회귀 테스트를 먼저 세운다(gen-verify).
- **데이터 거주/컴플라이언스**: 엔터프라이즈 요구 시 리전 분리 — Phase 3.
