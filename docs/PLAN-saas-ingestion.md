# 기획 — 멀티테넌트 SaaS 수집(인제스트) 아키텍처

> **이 문서는 기획서다.** 설계 의도와 그 이유를 남기는 것이 목적이고, 현재 동작의 사용법은
> [`../README.md`](../README.md) 과 [`OPERATIONS.md`](OPERATIONS.md) 가 소유한다.
> 아래 §0 이 **어디까지 구현됐는지**를 밝히므로, 본문의 미래형 서술을 현행 사실로 읽지 말 것.
>
> 상태: 초안(2026-08-09), 개정(2026-08-10), **구현 현황 반영(2026-08-10)**.
> 결정된 방향 — **멀티테넌트 클라우드 SaaS · 퍼스트파티 수집기 단일 경로 ·
> 클라이언트는 훅(실시간) + 백그라운드 수집(백필) 병행.**
>
> ⚠ **OTLP 경로는 제거됨(2026-08-10, PR #16).** 사유: 공식 Claude Code OTel 규약(`claude_code.*`)과
> 비호환인 자체 규약(`claude.*`)이라 "표준처럼 보이지만 표준이 아닌" 반쪽 자산이 됐다. 제품에서
> 제외하고 **퍼스트파티 수집기 단일 경로 + 멀티플랫폼 확장**으로 전환했다.
> 아래 OTLP 관련 서술(§3.1·§4·§7 Phase 2·§8)은 **이력으로만 남긴다 — 현행 설계가 아니다.**
> 삭제된 것: `POST /v1/logs` 수신구, `GET /api/usage/export/otlp`, `go/internal/otlp` 패키지,
> `docs/SPEC-otlp-claude.md`.

## 1. 목표

여러 조직(org)이 가입해 **자기 팀의 코딩 에이전트 사용량·비용**을 보는 SaaS. 각 개발자 머신에서
집계가 올라오고, 조직 경계로 완전히 격리된다.

> 개정(2026-08-10): 원안은 "표준 관측 파이프라인(OTel)을 쓰는 고객과 아무것도 없는 고객 둘 다"를
> 노렸으나, **OTel 경로를 제거하면서 온보딩 경로는 하나가 됐다** — 원커맨드 설치기(`/install.sh`)다.
> 목표 시간(5분 이내)은 유지되고, 실제로는 한 줄 실행 + 초기 백필로 끝난다.

## 2. 이미 가진 것 (재사용 자산)

| 자산 | 위치 | SaaS 에서의 역할 |
|---|---|---|
| 인테이크 엔드포인트 | `POST /api/usage` (`go/internal/httpapi/usage.go`) | 퍼스트파티 수집 경로의 뿌리 |
| 테넌트 격리 | `tenant` + RLS(`app.tenant_id`, `db/rlsguard.go`) | **멀티테넌시의 핵심** — org=tenant 로 그대로 승격 |
| 집계 스키마·멱등 | `intake`·`store`(session UPSERT) | 재전송 안전·증분의 기반 |
| 데이터 정책 필터 | `intake.safeKeyword`, `collector/internal/policy` | 시크릿·PII 서버/클라 이중 방어 |
| 수집기 | `collector/` (jsonl→POST, 멱등·증분) | 백그라운드 에이전트 경로 |
| 비용·통계 | `cost`·`stats` | 조직별 대시보드 그대로 |

**핵심: 백엔드의 80%는 이미 멀티테넌트다.** RLS·테넌트 주입이 서 있고, 인테이크가 멱등이다.
SaaS 화의 실제 작업은 **① 인증/온보딩 ② 인제스트 표면(퍼스트파티 단일) ③ 클라이언트(훅) ④ 운영**이다.

```
[개발자 머신]                         [클라우드 SaaS]
 Claude Code                          ┌─────────────────────────────────────┐
   │ SessionEnd 훅 ──(집계 푸시)──────▶│  Ingest Gateway                      │
   │                                   │   └─ /api/usage      (퍼스트파티)     │
 백그라운드 에이전트 ─(백필·누락보정)─▶│        │  정규화 → intake            │
   (~/.claude jsonl)                   │        │                             │
                                       │   인증: org 인제스트 키 → tenant     │
                                       │        │                             │
                                       │   store(RLS app.tenant_id) → pg      │
                                       │   dashboard(web) ── org 로그인 ──────│
                                       └─────────────────────────────────────┘
```

### 3.1 인제스트 표면 (단일 경로, 한 정규화)
- **퍼스트파티** `POST /api/usage` — 우리 집계 shape 그대로. 훅·에이전트가 쓰는 **유일한** 경로.
- 같은 정책 필터·같은 멱등·같은 RLS 를 통과한다. 표면 하나, 코어 하나.
- ~~**OTLP 호환** `POST /v1/logs` — 표준 OTel Collector/SDK 수신구~~ →
  **제거됨(2026-08-10).** 사유: 공식 Claude Code OTel(`claude_code.*`)과 비호환인 자체 규약이라
  제품에서 제외. 확장 방향은 OTLP 가 아니라 **멀티플랫폼(Codex·Gemini) 수집기**다.

### 3.2 클라이언트 (수집 소스, 병행)

> **구현 완료 — 다만 형태가 원안과 다르다.** 원안은 "훅 스크립트"와 "백그라운드 에이전트"를
> 별개 산출물로 봤는데, 실제로는 **하나의 수집기 바이너리**가 두 역할을 다 한다: 훅이 그
> 바이너리를 부르고, 바이너리가 증분 스캔을 한다. 산출물을 둘로 두면 페이로드가 갈라지므로
> 합쳤다. 또 원천이 Claude 하나가 아니라 **넷**으로 늘었다.

- **훅(신선도)**: Claude Code `SessionEnd` 훅이 수집기를 호출한다. 세션이 끝나면 바로 올라간다.
  Antigravity 는 `Stop` 훅이 같은 일을 한다(그쪽은 statusLine 스풀을 미는 것이 목적).
- **증분 스캔(완전성)**: 같은 수집기가 훅이 못 잡은 것(훅 미설치 기간·과거 세션·훅 실패)을
  파일 원천에서 백필한다. 증분 체크포인트로 중복 없음(서버 멱등이 2차 방어).
- **원천은 넷이다**(원안의 `~/.claude` 단일에서 확장):
  `~/.claude/projects/**/*.jsonl` · `~/.codex/sessions/**/*.jsonl` ·
  `~/.gemini/tmp/<슬러그>/chats/*.jsonl` · Antigravity 스풀(`~/.config/claude-usage/antigravity`).
- 전부 **같은 페이로드·같은 인제스트 키**를 쓴다. 세션마다 `platform` 필드로 갈린다.

### 3.3 인증 / 온보딩 (멀티테넌시)

> **구현 완료.** 다만 두 가지가 원안과 다르다 — 키 형식과 로그인 수단.

- 인제스트 키 발급 — **구현 완료.** 실제 형식은 `uu_ing_<rand>` 다(원안의 `uu_ing_<org>_<rand>`
  처럼 **org 를 키에 박지 않는다**). org 는 해시 조회로 알아내므로 키 문자열에 조직 식별자를
  넣을 이유가 없고, 넣으면 키 하나가 조직 이름까지 흘린다. 저장은 `sha256` 만, 평문은 1회 노출.
- 키 → tenant 매핑을 게이트에서 조회해 `app.tenant_id` 주입 → RLS 가 격리를 강제 — **구현 완료.**
- 대시보드 열람은 별도 **사용자 로그인** — **구현 완료(ID/PW 세션).**
  **SSO/이메일은 미구현**이다(Phase 3). 보고(intake) 키와 열람 자격은 분리돼 있다 —
  인제스트 키로 `/api/usage/*` 를 부르면 403, 해지된 키는 401.
- 설치 UX — **구현 완료, 원안보다 단순해졌다.** "훅 스니펫 + 에이전트 원라이너" 두 개를 붙여
  넣게 하지 않고, **원커맨드 한 줄**이 다운로드·설정·훅 등록·초기 백필을 다 한다:
  `curl -fsSL $SERVER/install.sh | sh -s -- --key <키> --server $SERVER`.
  "연동" 탭이 org 키가 박힌 그 한 줄을 복사해 준다.

## 4. ~~OTLP ↔ Claude 사용량 매핑~~ — 제거됨(2026-08-10, 이력)

> 이 절의 설계는 **더 이상 유효하지 않다.** 사유: 여기서 정의한 `claude.*` 확장은 공식 Claude Code
> OTel 규약(`claude_code.*`)과 비호환이라, 표준 파이프라인 호환이라는 원래 목적을 달성하지 못한다.
> 남은 것은 "표준처럼 보이지만 표준이 아닌" 자체 규약뿐이라 제품에서 제외했다.
> 왜 그런 시도를 했는지 알 수 있도록 아래 매핑안만 기록으로 남긴다.

- 표준: `gen_ai.usage.input_tokens`·`output_tokens` → input/output. `gen_ai.request.model` → 모델.
- **Claude 특수(표준에 없음)**: cacheRead·cacheCreate·`cc1h`(ephemeral_1h)·7축(tool·bash·slash·skill·
  agent·mcp·keyword) → `claude.*` 네임스페이스로 확장하려 했다 — **이 확장이 비호환의 원인이다.**
- 전송 단위: 세션=로그 레코드, 토큰=메트릭. 역방향 export(`GET /api/usage/export/otlp`)도 함께 제거했다.

## 6. 과금 훅

**미구현(Phase 3).** 사용량 기반 제품이라 과금이 자연스럽다 — 좌석 수 또는 관측된 세션/토큰량.
인제스트 키·tenant 단위로 카운트가 이미 잡히므로 미터링을 그 위에 얹으면 된다. 좌석 조회
(`GET /api/usage/seats`)까지는 서 있고, **미터링·청구 연동은 아직 없다.**

## 8. 리스크 / 오픈 이슈
- **훅 계약 안정성**(열림): 훅 이벤트/페이로드 스키마에 의존한다 — 버전 변화 대비 증분 백필이
  안전망이다. Antigravity 는 여기에 더해 **statusLine 출력 형식**에도 의존하므로 표면이 하나 더 넓다.
- ~~**OTLP 매핑의 표현력**~~ — **이 리스크가 현실화되어 OTLP 를 제거했다(2026-08-10).** 캐시·cc1h·7축을
  표준 속성으로 못 담아 `claude.*` 확장이 필요했고, 그 확장이 공식 `claude_code.*` 와 어긋나
  "표준 호환"이라는 목적 자체가 성립하지 않았다. 결론: 퍼스트파티 경로가 1급이 아니라 **유일**하다.
- ~~**멀티테넌트 전환의 실측**~~ — **해소됨.** 키→tenant 게이트·rate-limit 이 구현됐고 pg RLS
  크로스테넌트 격리를 실측했다([`VERIFICATION.md`](VERIFICATION.md) §3) + CI 상시 게이트.
- **단가 공백**(열림): 공식 단가가 없는 모델(`gemini-3.1-pro`·`gpt-oss-120b`)은 `unpriced` 로
  드러낸다. 추측 매핑을 넣지 않는 것이 의도이고, 그만큼 비용 합계가 **과소**임을 화면이 밝힌다.
- **구독 요금제와 비용 라벨**(열림): 화면 값은 "API 환산 비용"이지 청구액이 아니다. 라벨로
  방어하고 있으나, 경리에 그대로 넘기는 오용은 문서·라벨 밖에서 막을 수단이 없다.
- **데이터 거주/컴플라이언스**(열림): 엔터프라이즈 요구 시 리전 분리 — Phase 3.
- **쿼터 부재**(열림): rate-limit 은 순간 폭주만 막는다. 한 org 의 **누적** 사용량 상한이 없어
  스토리지·비용이 무제한으로 늘 수 있다.

## 9. 다음 액션

Phase 1·2 는 닫혔다(§0·§7). 남은 것은 Phase 3 이고, 그 대부분은 **코드 밖 결정**이 먼저다 —
결제 대행·SSO 공급자·데이터 거주 정책. 코드로 먼저 할 수 있는 것은 둘이다:

1. **per-tenant 쿼터** — 미터링의 전제이기도 하다(§6).
2. **셀프서브 가입** — 지금은 운영자가 `usage-server org create` + `key issue` 로 만들어
   전달한다([`OPERATIONS.md`](OPERATIONS.md)). 그 절차를 가입 폼 뒤로 옮기는 일이다.
