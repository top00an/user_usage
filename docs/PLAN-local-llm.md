# 기획 — 로컬 LLM 사용량 수집

> **이 문서는 기획서다.** 설계 의도와 그 이유를 남기는 것이 목적이고, 현재 동작의 사용법은
> [`../README.md`](../README.md) 과 [`OPERATIONS.md`](OPERATIONS.md) 가 소유한다.
> §0 이 **어디까지 구현됐는지**를 밝히므로, 본문의 미래형 서술을 현행 사실로 읽지 말 것.
>
> 상태: 초안(2026-08-21). **구현된 코드는 아직 없다** — 이 문서는 조사 결과와 동결한 계약이다.
>
> 결정된 방향 — **로컬 여부는 기록한다(추론하지 않는다) · 비용은 미등록으로 둔다 ·
> platform 은 원천당 하나를 유지한다.**

## 0. 구현 현황 (2026-08-21)

| 항목 | 상태 | 근거 |
|---|---|---|
| 로컬 LLM 수집 | **미구현** | 이 문서가 그 설계다 |
| 미등록 모델을 정직하게 처리 | **이미 구현됨** | `go/internal/cost/cost.go` — 모르는 모델은 `Priced=false`, 이름 보존, 조용한 $0 금지 |
| 오픈웨이트 모델의 단가 문제 인식 | **이미 문서화됨** | `go/internal/cost/seed_openai.go` 의 `openaiUnpriced` |

## 1. 왜 이것이 단순한 원천 추가가 아닌가

레포는 이 문제를 **이미 만나서 이름 붙여 놨다.** `seed_openai.go` 의 주석이다:

> `gpt-oss-120b` 는 오픈웨이트 모델이라 **호스팅 사업자마다 단가가 다르다** — 공식 가격표에
> 항목이 없고(2026-08-05 확인), **어디서 돌렸는지를 사용량 레코드가 말해 주지 않는다.**
> 아무 제공자의 단가나 골라 박으면 그 숫자가 맞는지 아무도 확인할 수 없다.

로컬 LLM 은 이 문장을 예외에서 **중심 사례**로 옮긴다. 그리고 세 가지가 동시에 깨진다:

1. **비용.** 로컬은 API 과금이 $0 인데 이 도구의 중심 질문이 "종량제였다면 얼마인가"다.
2. **귀속.** `usage_sessions` 에는 `platform` 과 `model` 뿐이다. 로컬 모델을 클라우드 에이전트가
   물고 돌면 **데이터에 로컬이라고 적힌 자리가 없다.**
3. **축 범위.** 원천마다 잴 수 있는 것이 다르다 — 이건 기존 4플랫폼에서 이미 겪은 문제이고
   `platform-coverage` 지원표가 그 답이다. 로컬 원천도 같은 대우가 필요하다.

②가 이 기획의 핵심이다. ①은 이미 답이 있고(§2.1), ③은 기존 패턴을 따르면 된다.

## 2. 동결한 계약

### 2.1 비용 — 미등록으로 둔다 (코드 변경 없음)

로컬 모델은 단가표에 없으므로 `Priced=false` 로 나가고 `Unpriced` 목록에 이름이 남는다.
화면은 "이 모델들은 비용에서 제외됐다"를 말하고 합계에 넣지 않는다. **이것이 현행 동작이고
바꾸지 않는다.**

환산가("클라우드로 했다면 $X")는 **넣지 않는다.** 그 숫자는 관측이 아니라 가정이고, 이 화면의
성격은 "근사를 정확한 값으로 위장하지 않는 것"이다(README). 단가 0 으로 등록하는 것도 하지
않는다 — `cost.go` 가 경계하는 "조용한 $0"과 한 걸음 차이이고, **등록 누락과 진짜 0 이
화면에서 같아 보이게** 된다.

> 부작용을 하나 받아들인다: 로컬 사용량의 '값'은 화면에 안 보인다. 토큰·세션·행동 축은 보인다.

### 2.2 로컬 여부는 **기록한다** — 모델명으로 추론하지 않는다

모델명만으로 로컬을 판정하려는 유혹이 있지만 `seed_openai.go` 가 이미 그것이 불가능하다고
적었다. 판정 근거는 **엔드포인트**이고, 그것을 아는 것은 수집기뿐이다.

계약:

```
payload.Session.Runtime  string  // "" (미보고=클라우드 하위호환) | "local"
```

- **판정은 수집기가 한다.** 로컬 엔드포인트(loopback · 사설 IP · 알려진 로컬 포트)를 보면
  `Runtime="local"` 을 싣는다.
- **엔드포인트 호스트명·포트·경로·토큰은 절대 보내지 않는다.** 그건 내부 인프라 정보이고,
  이 도구의 데이터 정책은 "필요한 최소만 저장"이다. 서버가 받는 것은 **판정 결과 한 낱말**이다.
- **빈 값이 하위호환의 전부다.** 현행 수집기는 이 필드를 보내지 않으므로 서버는 빈 값을
  클라우드로 읽는다(`platform` 필드가 `claude` 로 기본값을 갖는 것과 같은 규율).

이유: 호스트명을 저장하면 그 값이 곧 팀 내부망 지도가 된다. 판정은 클라이언트에서 끝내고
서버는 결과만 안다 — 그러면 저장된 것에서 되돌릴 정보가 없다.

### 2.3 platform 은 원천당 하나를 유지한다

`store/platform.go` 는 이 축이 **"세션을 만든 도구"** 를 재는 축이라고 못 박았고,
`gemini` 와 `antigravity` 를 나눈 근거가 "수집 가능한 축이 다르다"였다. 그 기준을 그대로 쓴다.

- **`codex-local` 같은 합성 값을 만들지 않는다.** platform 은 도구를 재는 축이고 로컬 여부는
  다른 차원이다. 한 축에 두 개념을 섞으면 지원표가 거짓이 된다.
- **`local` 하나로 접지 않는다.** Ollama 직접 대화와 opencode+로컬 모델은 잴 수 있는 축이
  전혀 다르다. 접으면 지원표의 `미수집`/`해당 없음` 구분이 무의미해진다.
- 허용목록(`store.Platforms`)에는 **파서가 실제로 데이터를 내기 시작할 때** 값을 추가한다.
  미리 넣으면 UI 에 영원히 빈 필터 항목이 남는다. 안 넣어도 데이터는 `other` 로 살아남고
  절대값 UPSERT 라 나중에 재전송하면 제자리를 찾는다.

## 3. 세 형태별 설계

팀이 셋 다 쓴다고 확정됐다. 작업량이 전혀 다르므로 갈라 적는다.

### 3.1 기존 에이전트 + 로컬 모델 — **새 파서 불필요**

Codex·Claude Code 의 `base_url` 만 로컬로 바꿔 쓰는 경우. 세션 파일에 토큰이 이미 남으므로
파서는 그대로다. `platform` 도 그대로다(도구는 여전히 Codex 다). 필요한 것은 §2.2 의
`Runtime` 판정뿐이다.

⚠ **미해결 — 판정 근거를 어디서 읽나.** 수집기 3종 전부 `base_url`·`provider` 를 읽지 않는다
(전수 확인). 세션 파일에 그 값이 남는지 자체가 미확인이고, 남지 않으면 설정 파일
(`~/.codex/config.toml` · `~/.claude/settings.json` 의 `ANTHROPIC_BASE_URL`)을 읽어야 한다.
**설정 파일을 읽는 것은 세션 시점의 값이 아니라 "지금" 값이라 과거 세션에 소급 적용하면
틀린다.** §5 의 샘플이 이 갈림길을 정한다.

또 하나: 로컬 엔드포인트는 캐시 축을 주지 않는다. `cacheRead`·`cacheCreate` 가 0 으로 오는데,
지원표는 이것을 **`해당 없음`** 으로 표기해야 한다(`미수집` 이 아니다 — 그 개념이 없다).
그런데 지원표는 **플랫폼 단위**라 "Codex 인데 로컬이라 캐시가 없다"를 표현할 자리가 없다.
→ §6 열린 결정.

### 3.2 Ollama · LM Studio 직접 — **새 파서 필요, 난이도가 갈린다**

| 런타임 | 원천 | 난이도 |
|---|---|---|
| **LM Studio** | 대화를 JSON 으로 저장한다 | **낮다** — 파일 기반. `gemini` 파서와 동형으로 만들 수 있다 |
| **Ollama** | 대화별 토큰이 디스크에 남지 않는다 | **높다** — Antigravity 패턴(런타임 캡처 → 스풀 → 훅 플러시) |

Ollama 의 응답에는 `prompt_eval_count`·`eval_count` 가 있지만 어디에도 저장되지 않는다.
`~/.ollama/history` 는 REPL 줄 기록이라 토큰이 없다. 즉 **토큰이 보이는 지점을 런타임에
붙잡아야** 하고, 그 구조는 `collector/internal/antigravity` 가 이미 만들어 뒀다 — 그것을
템플릿으로 쓴다.

⚠ 이 표의 "LM Studio 가 JSON 으로 저장한다"는 **미검증**이다. 이 머신에 두 런타임이 없어
경로·스키마를 확인하지 못했다(조사 시도가 툴 권한에 막혔다). 실물 없이 파서를 쓰면
"관측한 것만 싣는다"는 이 레포의 규율을 어기게 된다 → §5.

### 3.3 opencode · aider · cline — **도구를 먼저 정해야 한다**

원천당 파서 1개 + 지원표 1행이다. 구조는 §3.2 의 파일 기반 쪽과 같다. 다만 **어느 도구를
쓸지 정해지지 않으면 설계가 시작되지 않는다** — 세션 포맷이 도구마다 다르고 잴 수 있는 축도
다르다. 셋 다 지원하는 것은 파서 3개를 만든다는 뜻이다.

## 4. 웨이브 분해

샘플 의존성으로 갈랐다. 1차는 **지금 검증 가능**하고, 2차는 실데이터를 기다린다.

### 1차 — 샘플 불필요 · 지금 착지·검증 가능

| # | 무엇 | 오너 경계 | 검증 |
|---|---|---|---|
| W1-1 | `payload.Session.Runtime` 필드 + 수집기 판정 함수(순수 · 엔드포인트 문자열 → local 여부) | `collector/internal/payload/` · 신규 `collector/internal/runtime/` | 단위 테스트 — loopback·사설 IP·공인 IP·빈 값 |
| W1-2 | 인테이크가 `runtime` 을 받아 좁힌다(빈 값 → cloud, 허용목록 밖 → 거부하지 않고 cloud) | `go/internal/intake/` | 단위 테스트 + 골든 |
| W1-3 | `usage_sessions.runtime` 컬럼 + 마이그레이션(기본값 `cloud`, NOT NULL) | `go/internal/store/` · `migrations/` | sqlite·pg 양쪽 왕복 |
| W1-4 | 조회 필터 `?runtime=local\|cloud` + 모델별 표의 근거 열에 로컬 표시 | `go/internal/httpapi/` | 골든 스냅샷 추가 |
| W1-5 | 미등록 모델이 로컬 이름으로 와도 정직하게 나가는지 회귀 테스트(`qwen3-coder:30b` 류) | `go/internal/cost/` | 단위 테스트 |

W1-5 는 코드 변경이 아니라 **현행 동작을 못박는 테스트**다. `NormalizeModel` 의 변형 접미사
절단(`-thinking`·`-high`·`-medium`·`-low`)이 로컬 모델명을 건드리지 않는지도 여기서 본다.

### 2차 — 실데이터 샘플이 있어야 시작

| # | 무엇 | 선행 조건 |
|---|---|---|
| W2-1 | §3.1 의 `Runtime` 판정 근거 배선(세션 파일 vs 설정 파일) | Codex·Claude 세션 파일에 엔드포인트가 남는지 확인 |
| W2-2 | LM Studio 파서 | `~/.lmstudio` 실물 경로·스키마 |
| W2-3 | Ollama 런타임 캡처 | 토큰이 보이는 지점 특정 |
| W2-4 | opencode/aider/cline 중 **선택된 하나**의 파서 | 도구 결정 + 세션 파일 실물 |
| W2-5 | `store.Platforms` 확장 + 지원표 행 추가 | 해당 파서가 데이터를 낸 뒤 |

## 5. 필요한 실데이터 샘플

파서를 쓰기 전에 이것들이 필요하다. **이 레포의 규율은 "관측한 것만 싣는다"이고, 샘플 없이
쓴 파서는 그 규율 위반이다.** (이번 세션에 Codex `bash` 축이 정확히 그 이유로 침묵했다 —
파서가 구버전 이벤트 모양을 가정하고 있었고, 실데이터를 보기 전까지 아무도 몰랐다.)

1. **로컬 모델을 물린 Codex 또는 Claude Code 세션 파일 1개** — 엔드포인트가 기록되는지,
   모델 id 가 어떤 문자열로 오는지, 캐시 필드가 어떻게 오는지(0 인가 부재인가).
2. **LM Studio 대화 파일 1개** — 경로와 스키마. 토큰 필드 이름.
3. **Ollama 로 한 대화 1건** — 그리고 그 직후 `~/.ollama` 아래에서 토큰 숫자가 남은 파일이
   있는지. 없음을 확인하는 것도 결과다(그러면 런타임 캡처가 확정된다).
4. **§3.3 도구 결정** — opencode·aider·cline 중 무엇인가. 정하면 그 도구 세션 파일 1개.

전부 사용자 이름·경로·프롬프트 내용이 들어 있으므로 원문을 그대로 옮길 필요는 없다 —
**키 이름과 숫자 필드의 모양**만 있으면 된다.

## 6. 열린 결정

| # | 무엇 | 왜 지금 못 정하나 |
|---|---|---|
| D1 | 지원표(`platform-coverage`)가 플랫폼 단위인데, "Codex 인데 로컬이라 캐시 축이 해당 없음"을 표현할 자리가 없다. 행을 (platform × runtime)으로 늘릴지, 각주로 처리할지 | 표가 커지면 화면의 목적(플랫폼별 범위 차이)이 흐려진다. 실제 로컬 세션이 붙은 뒤 보는 게 맞다 |
| D2 | §3.1 의 판정을 세션 파일에서 읽을지 설정 파일에서 읽을지 | 세션 파일에 엔드포인트가 남는지 미확인. 설정 파일은 "지금" 값이라 과거 세션에 소급하면 틀린다 |
| D3 | §3.3 의 도구 선택 | 사용자 결정 사항 |
| D4 | 로컬 세션의 `project` 귀속 — 로컬 런타임 직접 대화는 워크스페이스 개념이 없을 수 있다 | 원천 스키마를 봐야 안다 |
