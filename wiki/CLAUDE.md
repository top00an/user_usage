# wiki/ — 이 지식베이스의 스키마

이 디렉터리는 **LLM 이 쓰고 사람이 읽는 위키**다. 사람이 직접 문서를 고치는 자리가 아니라,
LLM 이 원천(레포의 코드·문서·커밋)을 읽고 **누적해서** 유지하는 컴파일 결과물이다.

RAG 와 다른 점이 하나다. RAG 는 질문마다 원문을 다시 뒤져 매번 처음부터 종합한다. 이 위키는
**한 번 종합해 두고 그것을 갱신한다** — 상호참조가 이미 걸려 있고, 모순은 이미 표시돼 있고,
"왜 그렇게 했는가"가 이미 페이지가 돼 있다.

---

## 3계층

| 계층 | 무엇 | 누가 쓰나 |
|---|---|---|
| **원천(raw)** | 레포 자체 — `README.md` · `docs/**` · `go/**` · `collector/**` · `web/**` · git 로그 | 개발자 (위키는 **읽기만** 한다) |
| **위키(wiki/)** | 이 디렉터리의 마크다운 전부 | **LLM 이 소유한다** |
| **스키마** | 이 파일 | LLM + 사람이 같이 진화시킨다 |

⚠ **위키는 원천을 절대 수정하지 않는다.** 위키를 고치다 코드가 틀렸음을 발견하면
[[risks]] 에 적고 사람에게 보고한다 — 코드를 고치는 것은 별개의 작업이다.

## 디렉터리 구조

```
wiki/
  CLAUDE.md        이 파일 — 스키마
  index.md         ★ 내용 카탈로그. 질의는 여기서 시작한다
  log.md           ★ 시간순 기록(append-only)
  overview.md      제품 한 장 요약 — 처음 오는 사람의 입구
  risks.md         열려 있는 리스크·미검증 항목 종합
  sources.md       원천 문서 목록과 각각이 무엇의 단일 출처인가

  systems/         돌아가는 것 — 서버·수집기·프런트·설치기·게이트·배포
  packages/        Go 패키지 단위 — 경계와 계약
  platforms/       수집 대상 4종 + 수집 범위 차이
  concepts/        결정과 불변식 — "왜 이렇게 돼 있는가"
  operations/      운영 절차 — 실행 가능한 것
  decisions/       되돌리기 어려운 선택의 기록(ADR 성격)
```

## 페이지 규약

### frontmatter (필수)

```yaml
---
type: system | package | platform | concept | operation | decision | hub
tags: [go, 비용, 멀티테넌트]
updated: 2026-08-12
sources: ["README.md", "go/internal/cost/cost.go"]
---
```

`sources` 는 **그 페이지가 무엇을 읽고 쓰였는가**다. 원천이 바뀌면 이 목록으로 갱신 대상
페이지를 역추적한다.

### 본문

- **첫 문단은 한 문장 요약**이다. 인덱스가 이 문장을 그대로 가져간다.
- 링크는 `[` `[페이지이름]` `]` 형태의 Obsidian 위키링크 — 폴더 무관, 파일명으로 해석된다.
  아직 없는 페이지를 링크해도 된다. 그건 오류가 아니라 **다음에 쓸 것**의 표시다.
- **원천 인용은 파일 경로로 못박는다** — `go/internal/cost/cost.go` 처럼. 줄 번호는 쓰지
  않는다(레포가 실제로 줄 번호 드리프트로 한 번 데였다 — `docs/PLAN-phase1-multitenant.md` 참조).
- 근거 없는 추론은 **"추정"이라고 밝힌다.** 이 레포의 규율이 그렇고([[honest-uncertainty]]),
  위키도 같은 규율을 따른다.

### 모순 표기

원천끼리 어긋나면 **한쪽을 고르지 말고 둘 다 적는다**:

> ⚠ **모순.** `docs/VERIFICATION.md` 는 백엔드 12 패키지라 하고 `.github/workflows/ci.yml`
> 의 스텝 이름은 11 이라 한다. 게이트 동작(`go test ./...`)에는 영향 없음.

## 작업 절차

### ① 수집(ingest) — 원천이 바뀌었을 때

1. 바뀐 파일을 읽는다.
2. `sources` 에 그 파일이 걸린 페이지를 전부 찾는다 (`grep -l '<파일경로>' wiki/**/*.md`).
3. 각 페이지를 갱신한다. **덧붙이지 말고 통합한다** — 낡은 서술은 지우거나 이력으로 내린다.
4. 새 개념이 생겼으면 페이지를 만들고 [[index]] 에 한 줄 추가한다.
5. [[log]] 에 항목을 추가한다.

### ② 질의(query)

1. [[index]] 를 먼저 읽는다 — 임베딩 검색 없이 여기서 후보를 고른다.
2. 후보 페이지를 읽고 답한다. 답에는 **위키 페이지 링크와 원천 경로를 함께** 단다.
3. 답이 재사용할 가치가 있으면 **페이지로 만들어 위키에 남긴다.** 대화창에서 사라지게
   두지 않는다 — 그게 이 위키가 RAG 와 다른 이유다.

### ③ 점검(lint) — 주기적으로

- 모순: 서로 다른 값을 말하는 페이지 쌍
- 낡음: `sources` 의 원천이 그 뒤 커밋으로 바뀐 페이지
- 고아: 어디서도 링크되지 않는 페이지
- 공백: 여러 페이지가 언급하는데 자기 페이지가 없는 개념
- 깨진 링크: 위키링크가 가리키는 `.md` 파일이 없는 것 → 만들 것인가 지울 것인가 결정

점검 스크립트(깨진 링크 · 고아 페이지):

```bash
cd wiki
find . -name '*.md' | sed 's#.*/##; s#\.md$##' | sort > /tmp/pages.txt
# 이 파일(CLAUDE.md)은 제외한다 — 아래 정규식 자체가 자기를 매칭한다
grep -ho '\[\[[^]]*\]\]' -r --exclude=CLAUDE.md . \
  | sed 's/\[\[//; s/\]\]//; s/|.*//' | sort -u > /tmp/links.txt
comm -23 /tmp/links.txt /tmp/pages.txt   # 깨진 링크
comm -13 /tmp/links.txt /tmp/pages.txt   # 고아 페이지
```

`CLAUDE.md` 는 스키마 문서라 **frontmatter 가 없다** — 위키 페이지가 아니다.

### 로그 형식

`log.md` 는 append-only 이고 각 항목은 이 접두사로 시작한다:

```
## [2026-08-12] ingest | README.md 개정 — platform 필드 추가
```

접두사를 고정하면 `grep '^## \[' wiki/log.md | tail -5` 로 최근 이력을 뽑을 수 있다.

## 이 레포에만 적용되는 규칙

1. **한국어로 쓴다.** 원천이 전부 한국어이고, 용어를 번역하면 원천과 대조가 안 된다.
2. **골든 44개는 신성하다.** [[golden-contract]] 를 고칠 때는 반드시 "골든을 손으로 고치면
   안 된다"는 규율을 함께 유지한다.
3. **미검증 항목을 검증된 것처럼 쓰지 않는다.** 원천이 "미검증"이라 적은 것은 위키도
   미검증으로 옮긴다. [[risks]] 가 그 목록의 단일 출처다.
4. **레포가 이미 소유한 사실은 위키가 다시 소유하지 않는다.** 예: 운영 절차의 단일 출처는
   `docs/OPERATIONS.md` 다. 위키의 [[runbook]] 은 그것을 **요약하고 링크**할 뿐, 명령어
   원문을 복제해 두 벌로 만들지 않는다. 복제하면 한쪽만 고쳐지는 날이 온다.
