# 문제 해결 — 증상에서 원인으로

`docs/OPERATIONS.md` §5 가 원문. 이 페이지는 **증상 → 원인 → 위키 링크** 색인이다.

## 401 — 자격이 안 먹었다

나오는 자리가 셋이고 원인이 다르다.

### ① 설치 중 `다운로드 실패` (`/api/agent/collector`)

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer <키>" "$SERVER/api/agent/collector?os=darwin&arch=arm64"
```

| 코드 | 뜻 | 할 일 |
|---|---|---|
| `401` | 키가 없거나·틀리거나·**해지됨** | "연동" 탭에서 목록 확인 → 새로 발급 → [[ingest-keys]] |
| `404` | os/arch 가 화이트리스트 밖 | `darwin`\|`linux` × `amd64`\|`arm64` 만 |
| `503` | 그 플랫폼 바이너리가 서버에 없음 | `scripts/build.sh` 로 재빌드·배포 |
| `200` | 키는 정상 | 원인은 네트워크·프록시 |

### ② 보고가 안 올라간다 (`POST /api/usage` 401)

가장 흔한 원인은 **키 해지**(운영자가 회전시켰는데 재설치가 안 됨). 원커맨드를 새 키로 다시
실행하면 된다 — 멱등이라 훅이 중복되지 않는다 → [[installer]].

**전 팀원이 동시에 401** 이면 다른 것을 의심하라 — 옛 sqlite DB 에 `ingest_keys.username`
컬럼이 없어 키 해석 질의가 통째로 실패하는 경우다. 원인이 인증처럼 보이는 자리 → [[go-org]].

### ③ 로그인이 401

계정·비밀번호 문제. 부팅 env 로 만든 관리자는 **이미 사용자가 있으면 만들어지지 않는다**는
점을 먼저 의심하라(멱등이라 비밀번호를 덮지 않는다). 확실히 하려면 `user add` → [[runbook]].

## 403 — 자격은 맞는데 범위 밖

거의 항상 원인 하나 — **인제스트 키·인테이크 토큰으로 조회를 시도**한 것. 조회에는 관리자
토큰이나 로그인 세션을 쓴다.

**상태변경이 403** 이면 **쿠키로 시도**한 경우다. 쿠키로는 조회만 된다 → [[auth-scopes]].

## 화면이 뜨는데 데이터가 없다

1. `GET /healthz` 가 200 인가 (무인증·무DB 프로브)
2. **커버리지 화면의 머신별 마지막 보고 시각** — 언제 끊겼는지가 여기 있다
3. 개발자 머신에서 수집기를 손으로 돌려 stderr 를 본다:

| 출력 | 뜻 |
|---|---|
| `세션 파일(*.jsonl)이 없다` | 그 CLI 를 안 썼거나 원천 경로가 다르다 |
| `보낼 것이 없다(모든 세션이 마지막 전송 이후 그대로다)` | **정상.** 새 활동이 없을 뿐 |
| `⚠ 압축된 롤아웃 N개를 건너뛴다(.zst)` | [[codex]] 가 7일 지난 세션을 압축한 것. **그만큼 빠진다**(알려진 한계) |

## 브라우저에서만 아무것도 안 된다

`USAGE_PORT` 가 브라우저 차단 포트(**4190** · 6000 · 6667 등)일 때의 증상. 서버는 정상
기동하고 curl 도 200 인데 브라우저만 죽는다.

지금은 **부팅에서 거부**하므로 이 상태로 뜨지 않지만, 옛 배포 설정을 쓰다 부팅이 거부되면
이 항목이다 → [[boot-gates]].

## 비용이 이상하다

1. **`unpriced` 목록을 먼저 보라.** 공식 단가가 없는 모델(현재 `gemini-3.1-pro`·
   `gpt-oss-120b`)은 비용에 잡히지 않는다. 그만큼 합계는 **과소**다.
2. 기동 로그의 `· 단가표: <경로>` 를 확인하라. **cwd 가 레포 루트가 아니면 `config.json` 을
   못 찾아 조용히 시드 단가로 떨어진다.** 배포에서는 `USAGE_CONFIG` 를 명시하는 편이 안전.
3. 화면 값은 **"API 환산 비용"** 이지 청구액이 아니다.

→ [[cost-model]]

## 모델 축에 `<synthetic>` 이 보인다

인테이크가 이제 접으므로 **앞으로 들어오는 보고에는 안 생긴다.** 이미 쌓인 행은
`cleanup placeholder-models` 한 번 → [[cleanup]].

## 모델별 합이 총계보다 작다

`①+②+③ == Totals` 불변식이 깨진 것이다. **사람에게는 "유실"로 보이지만 실제로는 집계
결함**이고, 골든이 잡아야 하는 항목이다 → [[model-three-paths]] · [[golden-contract]].

## pg 인데 남의 데이터가 보인다

**즉시 멈춰라.** `DATABASE_URL` 이 SUPERUSER 또는 BYPASSRLS 롤이면 RLS 격리가 통째로
무력화되는데 **증상이 없다**(요청은 200).

기동 로그를 확인:

```
  · DB 롤 확인 — 비-슈퍼·비-BYPASSRLS(RLS 테넌트 격리 성립)   ← 있어야 정상
  ⚠ DB 롤을 확인하지 못했다                                   ← 격리 미검증 상태로 뜬 것
```

→ [[tenancy-rls]]

## 화면이 옛 상태로 보인다

`Cache-Control: no-cache` 를 유지하고 있으므로 캐시 탓일 가능성은 낮다. `webroot/` 가 소스와
어긋난 채 배포됐는지 확인하라 → [[webroot-embed]].

## 골든이 갈린다

체크 순서:

1. `USAGE_KEYWORD_RETENTION_DAYS=off` 를 줬는가 (안 주면 스냅샷 3개가 갈린다)
2. 빈 DB 로 띄웠는가 (`totals.sessions != 0` 이면 하네스가 거부한다)
3. 3회 돌렸는가 (한 번의 초록불은 증거가 아니다)
4. `USAGE_CONFIG` 가 셸에 남아 있지 않은가

→ [[contract-harness]] · [[golden-contract]]
