# 사용자 관리 — 일상 운영

`docs/OPERATIONS.md` §9 가 원문. 최초 관리자는 §2([[runbook]]), 이 페이지는 그 뒤의 일상이다.

## API (관리자 전용)

| 메서드 | 경로 | 본문 |
|---|---|---|
| `GET` | `/api/admin/users` | — |
| `POST` | `/api/admin/users` | `{username, password, role?}` (기본 `member`) |
| `POST` | `/api/admin/users/role` | `{username, role}` |
| `POST` | `/api/admin/users/password` | `{username, password}` |
| `POST` | `/api/admin/users/team` | `{username, team}` |
| `POST` | `/api/admin/users/delete` | `{username}` |

비밀번호는 **최소 8자(룬 수)**. 평문은 요청 본문에만 존재하고 응답·로그·감사에 남지 않는다.

## ★ `sessionsRevoked` 와 `keysRevoked` 를 읽으세요

**"그 변경으로 그 사람의 자격을 실제로 거뒀는가"** 다.

안 거뒀다면 강등된 사람이 세션 만료까지 옛 권한을 그대로 들고 있거나, 지워진 사람의 수집기가
계속 보고하는데 — **요청은 200 이고 화면에는 아무 증상이 없다.** 이 두 응답 필드가 **그
침묵을 깨는 유일한 신호**다.

`keysRevoked: 0` 은 "거둘 키가 없었다"는 뜻이지 "안 봤다"가 아니다.

## 삭제(퇴사 처리)가 거두는 셋

| 거두는 것 | 응답 필드 | 안 거두면 |
|---|---|---|
| 계정 (`auth_users`) | `ok:true` | 로그인이 계속 된다 |
| 세션 (`auth_sessions`) | `sessionsRevoked` | 세션 만료(12h)까지 옛 권한으로 산다 |
| **결속 인제스트 키** | `keysRevoked` | **삭제된 이름으로 사용량이 계속 쌓인다** |

거두는 범위는 **그 사람에게 묶인 키만**이다. org 공용(레거시) 키와 남의 키는 건드리지 않는다
— **퇴사자 한 명이 팀 전체의 수집기를 멈추면 안 되기 때문이다.**

실측: 결속 키로 보고 200 → 삭제(`keysRevoked:1`) → **같은 키로 재보고 401**.

## 비밀번호 재설정은 키를 거두지 않는다 (의도)

재설정 이유의 절반은 단순 분실이다. 거기서 키까지 조용히 죽이면 그 사람의 수집기가 **아무
신호 없이** 멈추고, 아무도 그것이 재설정 때문이라는 것을 모른다.

그래서 재설정은 **세션만 끊고**, 살아 있는 키 개수를 `activeKeys` 로 알려 준다.

> ⚠ **침해가 의심되어 재설정한 것이라면 `activeKeys` 가 0 이 아닐 때 키도 함께 회전하라** —
> 그 키는 비밀번호와 무관하게 계속 보고할 수 있는 **쓰기 자격**이다 → [[ingest-keys]].

## 서버가 거부하는 것 (실측)

화면에서 버튼을 숨기는 것은 방어가 아니다.

| 시도 | 응답 |
|---|---|
| **마지막 관리자** 강등·삭제 | **409** `마지막 관리자는 강등·삭제할 수 없습니다 — 먼저 다른 관리자를 만드세요` |
| **자기 자신** 강등·삭제 | **409** `자기 자신은 강등할 수 없습니다` |
| member 가 `/api/admin/users` | **403** |
| 레거시 `usage_tok` 쿠키로 상태변경 | **403** |
| 없는 사용자 / 중복 생성 / 8자 미만 | 404 / 409 / 400 |

강등된 사용자의 세션은 **즉시 죽는다**(`/api/auth/me` → 401).

## 마지막 관리자 보호는 동시 요청에서도 선다

판정("지금 관리자가 몇 명인가")과 변경(강등·삭제)이 **한 트랜잭션**에서 일어난다.

> 예전에는 둘 다 세고 둘 다 바꿔 **관리자 0명**이 될 수 있었고, 그때 **두 응답 모두 200**
> 이라 화면·감사 로그 어디에도 사고로 보이지 않았다.

두 관리자를 동시에 삭제해도 하나만 통과하고 나머지는 409 다 — 어느 쪽이 통과할지는 경쟁이지만
**남는 수는 항상 1** 이다.

### 잠겼다면

API 로 우회할 방법은 **없다**(그것이 목적이다). DB 를 직접 손댔거나 마이그레이션 사고로
잠겼다면 서버 호스트에서:

```bash
usage-server user add -tenant default -username okcli -role admin
```

**DB 접근 자체가 권한**이다. 그 명령도 비밀번호 최소 8자를 강제한다 — 복구 자리에 약한
관리자 비밀번호가 들어가면 안 된다.

## 팀

`POST /api/admin/users/team` 이 기존 `team_members` 를 그대로 쓴다 — 팀별 롤업 화면
(`GET /api/usage/teams`)의 근거.

## 감사

전부 `usage_audit` 에 남는다 → [[go-identity]]. `actor` 는 로그인 사용자명, 관리자 토큰이면
`usage-admin`. **비밀번호는 어디에도 남지 않는다.**

## 퇴사 처리 순서 (재확인)

1. **§9 삭제** — 계정·세션·결속 키를 거둔다(그 시점부터 보고가 401)
2. **[[cleanup]] `usage-rows`** — 이미 쌓인 사용량 행을 지운다

거꾸로 하면 1과 2 사이에 훅이 한 번 더 돌아 방금 지운 사람의 행이 다시 생긴다.
